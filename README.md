# The Executive Architect Playbook

_My Personal Guide to Building AI Software Factories

This is my private operating manual, textbook, notebook, and mentor. It exists
to help me become an exceptional AI engineering executive and Executive
Architect of AI Software Factories.

It is not Mission Control documentation. Mission Control is one living case
study that I use to deepen my judgment. Product documentation remains in the
product repository.

## How this guide works

The guide helps me move through five levels:

1. understand;
2. explain;
3. implement;
4. debug; and
5. teach.

My deliberate-practice loop is:

`Study -> Explain -> Trace -> Build -> Operate -> Break -> Teach -> Reflect`

The guide records what I learned and how my thinking changed. It does not copy
product documentation.

## Boundaries

- Personal philosophy, growth, exercises, notes, and reflections belong here.
- Mission Control architecture, plans, ADRs, runbooks, and product evidence
  belong in Mission Control.
- Mission Control references identify the relevant document and studied commit.
- Original drafts remain preserved as source material.
- Sensitive notes stay under ignored private paths and never enter Git by
  accident.

## Status

This playbook is private and evolving. Its value comes from honest use, not
from appearing complete.
